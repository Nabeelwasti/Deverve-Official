# De VERVE application secret hierarchy

## Purpose-separated application keys
The provisioning workflow creates two Cloudflare Pages production secrets:
- `AI_KEYS_ENCRYPTION_KEY`: AES-GCM key for newly stored Gemini provider credentials.
- `CNIC_PREVIEW_HMAC_KEY`: HMAC key for new short-lived CNIC preview signatures.

They are independent random 256-bit secrets generated by the provisioning workflow and sent directly to the Cloudflare Pages API. They are not derived from `D1_BACKUP_ENCRYPTION_KEY` or `ADMIN_BOOTSTRAP_TOKEN`. The workflow never prints, commits or stores their values in GitHub; it provisions them once and refuses to overwrite existing keys. A non-secret hierarchy marker prevents accidental regeneration if one key is later missing. This removes `ADMIN_BOOTSTRAP_TOKEN` from new AI-key encryption and CNIC preview signatures. CNIC preview verification uses only `CNIC_PREVIEW_HMAC_KEY`; a preview link issued before the controlled deployment may need to be refreshed, and all links expire after two minutes.

## Migration and rotation
- Existing Gemini vault rows encrypted with the legacy bootstrap-derived key remain decryptable.
- When an owner/manager opens the AI key vault after the new secret bindings exist, the Worker re-encrypts legacy rows with `AI_KEYS_ENCRYPTION_KEY` and records an audit event.
- Do not rotate `ADMIN_BOOTSTRAP_TOKEN` until the AI key vault reports `legacy_keys_remaining = 0` and the owner has verified key access.
- The provisioning workflow checks existing bindings and patches only the two new names; a temporary Pages project test verified that this PATCH operation preserves unrelated environment variables.

## Important limitation
The two application keys are stored only as encrypted Cloudflare Pages production secrets. Separate owner password-manager escrow is not yet verified; losing either key would affect the corresponding encrypted data or preview flow. Independent off-account/offline recovery remains deferred until the business has its domain and business email. Never paste any of these secrets into chat, source code, issues or logs.
