## Material release blockers and risks

### 1. Production D1 migration — BLOCKER
- Production D1 is `deverve-production`, ID `355da876-17c4-4762-a59d-bb85f2e4551b`.
- Read-only production inspection confirmed that `discount_coupons` and `discount_coupon_redemptions` do not yet exist.
- Migration 0037 is therefore **not applied**. Deploying the merged Worker/UI before this migration would leave voucher management and coupon checkout paths unavailable.
- The connected Cloudflare API session can inspect production D1 and create/delete temporary databases, but D1 schema/data writes in the isolated restore attempt returned `SQLITE_AUTH`. No production SQL write was attempted.
- Required next action: reconnect/authorize Cloudflare with D1 Write access, then run a full restore rehearsal and apply migration 0037 in a controlled release.

### 2. Backup and restore — PARTIAL
- A D1 SQL snapshot was generated from production and uploaded to the private APAC bucket `deverve-db-backups` at `d1/deverve-production-2026-11-21.sql`.
- Object size: **139,921 bytes**. SHA-256: `c01febdb04569aceaa33c9a3aff4dd9d5350987a13cdb421904b8f9c8c4696fe`.
- The dump includes 62 application tables, 96 schema objects and 217 rows at the snapshot time. The bucket's managed public domain is disabled. D1 backup objects have a 35-day lock rule.
- This is a **same-account pre-migration snapshot**, not an independent off-account disaster-recovery copy. It has not passed an isolated restore drill. Temporary restore databases created during attempts were deleted; the production database was not modified.
- A separate encrypted off-account D1/R2 backup and proven restore remain mandatory. The D1 dump does not include the R2 CNIC image objects.

### 3. CNIC retention — owner/legal gate
- The live bucket retains rental evidence under an indefinite lock and the database prevents deletion/alteration. Customer-facing English and Urdu policy text describes this as the current owner-instructed operational policy.
- This is **not** a legal opinion that indefinite retention is required or lawful. Obtain review from qualified Pakistan counsel before changing retention, granting exceptions or promising a deletion period. Do not weaken the lock or evidence triggers casually.

### 4. Inventory accuracy — physical reconciliation
- Production snapshot: 5 product records, 7 active variants, 1 vehicle, 1 rental request, 2 rental documents and 13 media assets.
- Trouser has one legacy shared-stock row combining four sizes and five colours under one aggregate quantity (2,000) with no SKU/barcode. It must be physically counted by exact size/colour before splitting stock.
- Tolaza has an M variant with missing colour and a product-image/description colour mismatch. T2 has no attached product photos. Do not invent stock, colours, photos or brand-authenticity claims.

### 5. Payments, messaging and operational acceptance
- Cash on Delivery remains the only active checkout payment method. Safepay consumer queue/consumer bindings and provider sandbox acceptance are not complete; do not enable online payments.
- Resend/WhatsApp provider setup and actual customer delivery tests remain outstanding. Coupon issuance currently returns the generated code to the authorized admin for one-time copying/sharing; automatic email/WhatsApp delivery is not implemented or claimed.
- Turnstile production challenge/token acceptance, authenticated AI-key decryption and a real Gemini response, Android physical camera/barcode/QR acceptance, POS/finance reconciliation, rental workflow acceptance and final owner sign-off remain open.
- The remote D1 integration suite remains skipped in CI because test credentials are missing. FakeD1 and schema tests do not prove live D1 transaction isolation or restore behavior.
