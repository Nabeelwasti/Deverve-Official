## Executive assessment

The project is a substantial React/TypeScript storefront and business operations platform backed by Cloudflare Pages Functions, a Cloudflare Worker, D1 and private R2. The repository includes product catalogue and variants, stock, POS, orders, customers, wholesale, vehicle rentals, CMS, notifications, finance, staff permissions, audit history and an AI administration interface.

The latest CI run observed for the audited commit was GitHub Actions run #1390 (run ID `44738868197`), completed successfully. The remote D1 integration step was skipped because the required GitHub Cloudflare credentials were not configured. A green workflow therefore does not establish live provider acceptance or full production readiness.

**Release verdict: NOT YET PRODUCTION-ACCEPTED.** Cloudflare Pages deployments are intentionally disabled. Do not deploy, enable automatic deployment, or apply production migrations without an explicitly authorized release and verified recoverable backup.

### Additional Cloudflare read-back

A subsequent read-only Cloudflare API check confirmed the `deverve-media-private` bucket is in APAC and has an enabled indefinite R2 Bucket Lock rule (`deverve-rental-cnic-indefinite`) for `rental-private/`. Its managed `r2.dev` domain is disabled. A read-only Queue listing returned no queues in the account; the Safepay queue producer/consumer and DLQ therefore remain unconfigured. The Pages production configuration exposes D1 and private R2 bindings; secret values are masked by Cloudflare and cannot be inferred from the API response.

### Inventory anomaly

The four production product variants include one legacy row containing multiple size/colour options in one record. One variant lacks a SKU and one lacks a barcode. The production query found no variant whose on-hand stock was below reserved stock at that moment.

This legacy row is excluded from the unique normalized active-option index because it encodes multiple options in a single value. The storefront splits those values for selection, but they still share one underlying stock record. This is a data-integrity and stock-accuracy risk.

**Required action:** identify the affected product, physically count stock by actual size/colour, create one row per real combination with unique SKU/barcode, reconcile the original quantity without duplicating it, and test product selection, checkout, POS and reservations. Do not auto-split or duplicate production stock without verified counts and a recoverable backup.

## Findings and priorities

### P0 — Release blockers

1. **Independent backup and recovery:** the independent off-account D1/R2 backup and verified restore drill remain outstanding. A same-account backup or Time Travel alone is not sufficient. Verify encrypted export, independent storage, object recovery, database restoration and documented recovery steps before any risky production operation.
2. **Legacy product variant:** reconcile the multi-option row and missing SKU/barcode using physical stock counts. Do not invent stock values or duplicate inventory.
3. **Payment release gate:** Safepay code includes signature verification, event identity/digest checks and order/ledger reconciliation. The separate queue consumer, queue/DLQ configuration, production bindings and end-to-end sandbox acceptance remain incomplete. Until configured and tested, treat the synchronous fallback as the only available path and keep dynamic gateway checkout disabled unless a complete approved acceptance has been recorded.
4. **External provider acceptance:** Resend, Meta WhatsApp and payment credentials/templates/merchant setup must be configured in Cloudflare secrets and verified using business-controlled test destinations. No credentials should be committed to Git or sent in chat.
5. **Production evidence retention:** the Cloudflare API was subsequently queried read-only. Bucket `deverve-media-private` has an enabled indefinite lock rule named `deverve-rental-cnic-indefinite` scoped to `rental-private/`. The managed `r2.dev` domain is disabled. This resolves the documentation ambiguity for the current read-back. Never delete CNIC documents.

## Security observations

Positive controls observed in inspected source include server-side session checks, HttpOnly/Secure/SameSite=Strict cookies, PBKDF2-SHA256 password hashing, login throttling, server-side role checks, parameterized SQL in inspected paths, Turnstile integration, private R2 media access, audit logging and security response headers.

These observations do not constitute a full security certification. A complete Git-history secret scan, dependency and supply-chain review, authorization matrix testing, rate-limit abuse testing, cross-account isolation testing and external penetration test remain recommended.

The AI key vault can use a fallback derived from the admin bootstrap token when a dedicated encryption secret is absent. Verify a dedicated `AI_KEYS_ENCRYPTION_KEY` is configured and validate recovery before rotating related secrets.

## Follow-up implementation — 20 November 2026

- Added a best-effort continuous autofocus constraint where supported.

- Physical Android/iOS camera, torch, focus and label-reading acceptance remains outstanding. Do not describe the scanner as universally perfect across every device.

### Admin AI direct actions

The owner/manager direct command executor now supports six audited operations:

1. Publish one exactly identified product.

## Follow-up Cloudflare recovery verification — 20 November 2026

A read-only inspection found an existing APAC R2 bucket `deverve-db-backups` and an existing dated media restore-drill bucket. The database backup bucket was empty; no D1 SQL export was present.

The following protective changes were made through the Cloudflare API and then independently read back:

- `deverve-db-backups`: 35-day minimum retention for `d1/` and `media/`; indefinite retention for `rental-private/`.
- Dated R2 restore-drill bucket: indefinite retention for `rental-private/`. This bucket contained private rental evidence copies, so the rule was aligned with the source bucket's indefinite evidence protection.
- The source `deverve-media-private` bucket's existing indefinite `rental-private/` lock was re-read and remains enabled.

A non-destructive listing comparison found 15 source objects and 15 corresponding restore-drill objects, with no missing or extra keys and matching sizes/ETags (1,522,058 bytes). This validates object-list consistency at the time of comparison only. ETags were not treated as SHA-256 checksums. No object content was changed, no CNIC evidence was deleted, and no production D1 query/export/import or production application deployment was performed.

**Remaining P0 recovery gaps:** the D1 backup bucket is still empty; no scheduled D1 export Workflow, encryption key, off-account Dropbox copy, offline copy, alerting or isolated D1 restore has been verified. Both R2 buckets are in the same Cloudflare account, so they do not protect against account-level compromise or loss. Disaster recovery remains not production-ready.

The follow-up Cloudflare changes do not alter the Pages deployment setting. Source-triggered, production and preview deployments remain disabled.

## Storefront collection routing and live catalogue correction — 20 November 2026

A read-only production D1 query confirmed the current published test products are stored with the intended audience values: Choco = `women`, Testing = `kids`, Tolaza = `men`, and Trouser = `unisex`. No production product rows were modified.

The defect was in the Fashion screen collection cards: their artwork and secondary link sent customers to WhatsApp enquiries instead of opening the filtered live catalogue. The screen-first storefront intentionally keeps those cards hidden on the home screen; customers enter Fashion through the hero navigation, then choose an audience collection. The collection cards now route to the Fashion catalogue with their audience/collection filter selected.

The catalogue filter now normalizes common audience labels and product-category synonyms, including Women/Women's Fashion, Kids/Children, Men, Essentials, Hoodies & Jackets, and Trousers & Pants. It filters using the product's persisted `audience` for audience collections and `category` for garment-type collections. Automated browser coverage was added for the women and kids collection journeys. This code change requires CI success and has not been deployed to production.
