The repository includes product catalogue and variants, stock, POS, orders, customers, wholesale, vehicle rentals, CMS, notifications, finance, staff permissions, audit history and an AI administration interface.

### Inventory anomaly

The four production product variants include one legacy row containing multiple size/colour options in one record. One variant lacks a SKU and one lacks a barcode. The production query found no variant whose on-hand stock was below reserved stock at that moment.

This legacy row is excluded from the unique normalized active-option index because it encodes multiple options in a single value. The storefront splits those values for selection, but they still share one underlying stock record. This is a data-integrity and stock-accuracy risk.

**Required action:** identify the affected product, physically count stock by actual size/colour, create one row per real combination with unique SKU/barcode, reconcile the original quantity without duplicating it, and test product selection, checkout, POS and reservations. Do not auto-split or duplicate production stock without verified counts and a recoverable backup.

## Findings and priorities

### P0 — Release blockers

1. **Independent backup and recovery:** the independent off-account D1/R2 backup and verified restore drill remain outstanding. A same-account backup or Time Travel alone is not sufficient. Verify encrypted export, independent storage, object recovery, database restoration and documented recovery steps before any risky production operation.
2. **Legacy product variant:** reconcile the multi-option row and missing SKU/barcode using physical stock counts. Do not invent stock values or duplicate inventory.
3. **Payment release gate:** Safepay code includes signature verification, event identity/digest checks and order/ledger reconciliation. The separate queue consumer, queue/DLQ configuration, production bindings and end-to-end sandbox acceptance remain incomplete. Until configured and tested, treat the synchronous fallback as the only available path and keep dynamic gateway checkout disabled unless a complete approved acceptance has been recorded.
4. **External provider acceptance:** Resend, Meta WhatsApp and payment credentials/templates/merchant setup must be configured in Cloudflare secrets and verified using business-controlled test destinations. No credentials should be committed to Git or sent in chat.
5. **Production evidence retention:** documentation has conflicting statements about the indefinite R2 Bucket Lock rule. Verify the actual Cloudflare bucket rule and retention scope directly, and record the evidence. Never delete CNIC documents.

### P1 — Business workflow acceptance

- Complete verified product catalogue, price, size/colour combinations, SKU, barcode, stock and genuine media.
- Complete vehicle fleet, pricing, availability, rental policies and photos.
- Test POS cash handling, shifts, refunds, inventory reconciliation and financial ledger with the owner.
- Test order fulfilment, delivery fee approval, cancellation, exchange and replacement stock.
- Test wholesale quotation, customer approval and order conversion.
- Test rental booking, overlap protection, private CNIC access and staff authorization.
- Test email delivery/retry and WhatsApp opt-in/template delivery.
- Confirm owner-approved policies, privacy notice, contact details and delivery coverage.

### P2 — Engineering hardening

- Enable isolated remote D1 integration tests using dedicated test credentials and a non-production database.
- Add post-deployment smoke checks as a release gate, without enabling deployment automatically.
- Verify the dedicated `AI_KEYS_ENCRYPTION_KEY` is configured and test key recovery before rotating bootstrap secrets.
- Split oversized Worker/Admin/App files incrementally, preserving existing API behavior.
- Expand AI action coverage only through audited, role-checked, idempotent server-side operations.
- Complete physical-device acceptance for Android/iOS camera scanning, barcode hardware, accessibility and responsive behavior.
- Run a complete Git-history secret scan and dependency review before release.

## Security observations

Positive controls observed in inspected source include server-side session checks, HttpOnly/Secure/SameSite=Strict cookies, PBKDF2-SHA256 password hashing, login throttling, server-side role checks, parameterized SQL in inspected paths, Turnstile integration, private R2 media access, audit logging and security response headers.

These observations do not constitute a full security certification. A complete Git-history secret scan, dependency and supply-chain review, authorization matrix testing, rate-limit abuse testing, cross-account isolation testing and external penetration test remain recommended.

The AI key vault can use a fallback derived from the admin bootstrap token when a dedicated encryption secret is absent. Verify a dedicated `AI_KEYS_ENCRYPTION_KEY` is configured and validate recovery before rotating related secrets.

## AI assistant execution boundary

The admin AI inbox supports natural-language conversation, saved task history, product/file analysis and research. Direct audited actions currently cover:
1. Publish one clearly identified product.
2. Publish eligible draft products.
3. Set stock for one exact SKU.

Other business operations remain advisory or require their dedicated workspaces. Do not describe the assistant as fully autonomous or claim that an action was completed unless the backend confirms it.

## Safe remediation sequence

1. Keep Cloudflare deployment disabled.
2. Create and independently store encrypted D1 and R2 backups; perform a restore drill.
3. Verify CNIC Bucket Lock and retention settings directly.
4. Physically reconcile the legacy multi-option product variant and assign SKU/barcode values.
5. Configure Safepay queue/DLQ and isolated test D1; complete sandbox webhook/retry/ledger acceptance.
6. Configure Resend and WhatsApp using owner-managed provider accounts and secrets; verify consent and delivery.
7. Complete owner acceptance of catalogue, fleet, POS, finance, fulfilment, wholesale and rental workflows.
8. Add remote D1 integration and release smoke gates.
9. Re-run CI and independent security review.
10. Only after owner approval, backup verification and all release gates, prepare a separately authorized deployment.
